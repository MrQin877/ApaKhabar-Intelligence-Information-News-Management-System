# News engagement MVP

## Architecture and rollout

News, users, comments and likes use SQL Eloquent models (MySQL in deployment, SQLite in tests). MongoDB is used elsewhere in this repository; no engagement collection or MongoDB index is introduced. Keeping engagement with its parent records permits foreign keys and transactional counter updates. The existing unique likes(postID,userID) index is retained. Like model timestamps now match its created_at-only schema.

Run `php artisan migrate` before serving the updated application. Migration 2026_10_19_000001 adds nullable guest authors, moderation fields, a unique submission hash, the news/status/time comment index, news_viewers with a unique news/viewer pair, expiring news_visits, unique comment/user reports, and moderation history. It adds news.unique_views; news.view remains total views. Existing comments default to pending_review because they were never checked. Review them at /admin/comments. Existing total views remain historical legacy fetch counts; only new events use qualified view semantics. Unique counts begin at zero. Rollback keeps userID nullable to preserve guest comments, but removes engagement metadata.

Set server-side OPENAI_API_KEY and optionally ENGAGEMENT_ANONYMOUS_RETENTION_DAYS (default 90). Never use a VITE_ prefix for the key. The implementation calls https://api.openai.com/v1/moderations using omni-moderation-latest, according to https://developers.openai.com/api/docs/guides/moderation. Only comment content is sent; names, user IDs and cookies are not. Missing key, connection failure, timeout, HTTP error or malformed output holds the comment for review. No additional account verification is introduced.

Build assets with `npm run build`. Keep the Laravel scheduler running (`php artisan schedule:work` in development or schedule:run each minute in deployment). For Docker/cloud, inject the variables into the PHP container, configure the existing SQL connection and persistent shared sessions/cache, run migrations once, run the scheduler, and allow outbound HTTPS to api.openai.com. No new PHP extension or package is required. APP_KEY must be consistent across replicas; use HTTPS and secure session cookies in production. The repository only supplies a translation-service Compose file, not a complete Laravel Docker stack. Container execution was not verified because the Docker daemon was unavailable.

## Permissions and workflows

Guests read and submit comments without entering a name. The backend assigns each new guest comment a random display name such as guest123123 and stores it with the comment. Client-supplied guest names are ignored; existing comments retain their names. Like and Share open an accessible Login/Register/Cancel dialog. Registered users toggle likes, copy the canonical public article URL, comment, reply, and report. Existing mobile bearer-token comment/like/reply routes retain authentication and gain throttling; guest browser comments use CSRF-protected web routes. Mobile guest submissions are not introduced.

Comments render as React text. Public responses allowlist author, ID, text and date only and include published comments whose entire ancestor chain is published. All submitted replies pass moderation too. The admin portal uses existing auth/verified/role middleware and adds pending, reported, published, rejected and removed queues with pagination. Approve/reject apply only to pending comments; remove applies only to published comments; restore applies only to removed comments. Rejected comments cannot be restored. Decisions and report resolution are transactional, require a reason, and retain history. A removed comment was previously published or explicitly approved, making it eligible for restoration by a moderator.

Guest anti-bot protection combines a hidden honeypot, encrypted session/article-bound challenge, minimum reading delay, expiration, CSRF and rate limiting. This is basic bot resistance, not a CAPTCHA or proof of humanity. Comment/reply limits are five per minute; other engagement endpoints are throttled. Identical normalized text on the same article is rejected across authors, backed by a unique hash and a transaction. This conservative MVP policy also rejects repeated short phrases. Link/promotion patterns hold comments for review even if AI passes. Moderation is not a misinformation detector or comprehensive spam/profanity detector.

## View counts and privacy

Article GETs, prefetches and API polling perform no view writes. A separate session-bound encrypted token is issued without recording a view. React counts approximately 5.5 seconds of visible time, emits once per mount, and submits that token. The backend requires at least five seconds, validates article/session/expiry, and atomically deduplicates visit events. Client visibility cannot prove human attention or prevent a determined automated client; throttling limits abuse.

Authenticated keys use the user ID. Anonymous keys are keyed hashes of a random UUID in an encrypted first-party HttpOnly SameSite=Lax cookie (Secure on HTTPS). No IP is stored as a viewer identifier. IP may still be used by Laravel throttling. Anonymous identifiers expire after the retention period and visit tokens after two days; the daily scheduler purges these rows, retaining aggregate counts. Cookie expiry, deletion, different browsers, login transitions and retention expiry can produce extra estimated unique visitors. Authenticated identity records persist for deduplication; include them in any future account-erasure process. The public UI labels unique visitors; admin moderation shows total and unique aggregate analytics. Document this cookie and the OpenAI comment check in the site's privacy notice before rollout.

## Optional guest ownership linking (disabled / not implemented)

Fortify browser sessions and nullable comment.userID support opt-in claiming without another email/phone verification step. Implementation complexity is moderate: add a unique hashed 32-byte random claim token, expiry and claimed_at; keep the raw token in an encrypted HttpOnly SameSite cookie with bounded size/count; present authenticated users with a preview and explicit confirmation; lock each comment, require userID IS NULL and a valid unexpired token, assign the authenticated ID and invalidate the token atomically. Preserve content/time/status and audit the claim. A dedicated feature flag should default off. Never infer ownership from IP, name, email or comment ID. Tokens would apply only to new guest comments; legacy comments cannot be securely attributed. Browser-cookie size, cross-device claims and account switching require explicit UX decisions. No auto-linking occurs in this MVP.

## Validation and remaining manual checks

`php artisan test --filter=EngagementTest` covers guest/auth permissions, all registered roles, toggling and persistence, total/unique counts, event replay, cookie identity, token tampering/expiry, guest bot checks, multilingual input, flagged results, API failures, spam, duplicates, reports, moderation transitions, archive visibility, replies and rate limiting. `node --test tests/js/news-engagement.test.mjs` covers canonical clipboard copying, denial/unavailable API, hidden time, timer suspension and single-event emission. Existing ViewNewsTest remains compatible. API tests mock responses: they verify integration behavior, not real-world classification accuracy. Live English/Indonesian/slang quality evaluation still requires an approved representative dataset and a configured API key.

Before rollout, browser-smoke-test keyboard focus in dialogs, responsive layout, session expiry, copy permissions on HTTPS, five seconds with hidden/visible transitions, and admin queues. Validate the migration and concurrent likes/views against the deployment MySQL engine and run the deployment's Docker stack. SQLite tests exercise constraints and transaction paths but do not establish production lock behavior under load.
